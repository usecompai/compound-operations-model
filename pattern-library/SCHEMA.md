# Pattern format

Each YAML file identifies a reusable method: id, domain, title, required context, procedure, conditions and risks. `status: reference_pattern` means it needs configuration and verification in the adopting company.

No field should contain deployment counts, measured business results, costs or private operational telemetry. Do not treat percentages or renamed locations as anonymisation.

Keep executable sample inputs fictional. Use named configuration values for policy thresholds. Require the appropriate approval before external communication or consequential actions.

Verify input definitions, source permissions, failure handling and the resulting artifact. A pattern is not proof that a workflow is deployed or autonomous.
